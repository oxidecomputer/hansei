= Durin

A suite of tools for creating and using debug information — illumos CTF and DWARF-derived debug bundles — for
Rust binaries.

Experimental and mostly untested, expect bugs.

== Tools

These are the workspace members that may be useful:

* dwarf2ctf: Convert DWARF to CTF for specified types.
* durin: Read and write CTF files.
* exegesis: Read DWARF and extract *debug bundles* describing a binary's async runtime; also the bundle format's
  reader and type views.
* hansei: Inspect the state of the `tokio` multi-threaded runtime in a core dump or live process: task listings,
  automatic await-chain traces, and task dependency graphs with futurelock detection (bundles); scheduler dumps
  and polling (CTF).
* hansei-types: The tokio-introspection library behind hansei, generic over both debug-info backends.
* proc: Minimal bindings for illumos `libproc`, plus replayable target snapshots.
* reify: Interpret a process's memory through a debug-info backend (CTF or bundle).

== What's with the name?

In _The Lord of the Rings_, Durin is Gimli's father, `gimli` being the excellent DWARF library for Rust. The joke doesn't quite work as
DWARF is actually older than CTF, oh well.
