= Hansei

> https://en.wikipedia.org/wiki/Hansei[Hansei] (反省; "self-reflection") is a central idea in Japanese culture, meaning
to acknowledge one's own mistake and to pledge improvement.

A tool to inspect where we have erred with `tokio`: it reads the state of a tokio multi-threaded runtime from a
core dump — written by illumos or by Linux, and read on either — using debug information produced from a
*separate* build of the same sources. Currently a proof-of-concept, expect bugs.

hansei reads a debug *bundle* produced by `exegesis extract` (targets built with rustc ≥ 1.97): `exegesis`
reads a debug binary's DWARF and writes a compact bundle describing the async runtime. Task futures are joined
between the debug binary and the target by their v0-mangled symbol names, so tasks are selected by id and their
await chains are recovered fully automatically.

== Building

On illumos, `libproc-sys` generates its bindings with `bindgen`, which in turn uses `libclang`. Ensure that the
following are set, adjusting the LLVM version as-needed:

[source,shell]
----
export LIBCLANG_PATH=/opt/ooce/llvm-15/lib
export LD_LIBRARY_PATH=/opt/ooce/llvm-15/lib:$LD_LIBRARY_PATH
----

== Usage

Build the binary with the same target platform, commit, toolchain, and flags as the target binary, but with full
debug information (an optimized profile with `debug = true`). Both compilations then contain the same struct layouts,
though the build hash will be different in the mangled name. Stripping the hash, we can use that and the struct
layout as the join key that lets layouts from one binary interpret memory from the other.

Extract the bundle:

[source,shell]
----
cargo run --release -p exegesis -- extract ${PATH_TO_DEBUG_BINARY} -o app.bundle
----

Then attach to a target. The core and the bundle name the *session*, and are the only things the command line
takes; commands are read from stdin:

[source,shell]
----
hansei --core ${PATH_TO_CORE} --bundle app.bundle
----

When stdin is a terminal this is a prompt, and the session stays attached so each command reads the target
already in hand:

----
hansei〉tasks
hansei〉trace 3 -v
hansei〉graph ! grep -A5 futurelock
hansei〉quit
----

Tab completes command names, `!` pipes a command's output into a shell command, `info` reports what is attached
and how completely the bundle's symbols resolved, and `help` lists the commands. A command that fails ends the
command, not the session.

When stdin is not a terminal the same commands are read one per line — blank lines and `#` comments are
skipped — which is how scripts and the test suites drive it:

[source,shell]
----
echo "trace ${ID} -v" | hansei --core ${PATH_TO_CORE} --bundle app.bundle
----

There a failing command is fatal: the session stops at it and exits non-zero, rather than running the rest of
the script against a question it could not answer.

Cores can be read cross-platform, e.g., read an illumos core on Linux, a Linux core on macOS.

Each task is listed with its id, lifecycle state, concrete future type, spawn location, and where the future is
defined. `trace` prints one task's await chain, selecting it by the id from `tasks`:

----
hansei〉trace ${ID} -v
----

This prints every future in the chain with its suspend state and the source line of the awaited expression;
`-v` adds the live locals at each await point. When the chain bottoms out in a recognized wait primitive, hansei
also reports what the task is actually waiting on:

* `tokio::time::Sleep` — the registered timer deadline;
* `JoinHandle<T>` — the id of the awaited task (a dependency edge between tasks);
* `tokio::sync::batch_semaphore::Acquire` — the contended `Mutex`/`RwLock`/`Semaphore`, its permit counts,
  and its wake queue: the tasks its permits will wake, in order.

Those edges assemble into the runtime-wide dependency graph:

----
hansei〉graph
----

which prints one wait edge per task and diagnoses any *futurelock* (RFD 609): a lock future found in a
suspended frame's locals — off its task's poll path, so it will never be polled again — while granted, or
queued for, a contended semaphore's permits. The diagnosis names the holding task, the local and frame
the abandoned future is parked in, and the tasks blocked behind it.

At attach time the bundle's symbol fingerprint is resolved against the target's symtab; anything less than a
100% match is refused (`--force`/`-f` to override) so a wrong bundle can never silently misinterpret memory.

The `snapshot` command captures everything a bundle-backed analysis reads from a target into a small replayable file;
together with a bundle extracted from a *separate* build it feeds the offline two-binary tests in
`hansei-types/tests`.

== Testing

* `cargo test` — cross-platform unit tests and the offline two-binary snapshot tests. On Linux this also runs
  `tests/linux.rs`, which builds the `core-tokio` fixture, extracts a bundle from it, dumps a core with gdb's
  `gcore`, and drives all three commands over the result.
* `cargo test --features illumos-integration -- --ignored` (on illumos) — the on-box suite: fixtures built and
  run for real, cored at their parked steady state, output compared against known-good renderings.
